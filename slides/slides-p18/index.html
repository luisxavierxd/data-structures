18.1 Trees and cycles

Graphs without cycles.

18.1 · Trees and cycles

A tree is a connected graph with no cycles

  • Connected: a path between any two vertices.
  • No cycles: that path is unique.
  • V − 1 edges: remove one, it splits. Add one, a cycle appears.
Any two of these three facts give you the third.

Undirected graphs. Adapted from de la Cueva et al. (2020), Fig. 10.12.

18.1 · Trees and cycles

How do I find a cycle?

Use DFS

  • Kahn's algorithm (P17) says if there is a cycle, but not which one.
  • BFS works only on undirected graphs.
Checkpoint

An undirected graph has 5 vertices and 4 edges: 1–2, 2–3, 3–1 and 4–5. Is it a tree?

A. Correct. 1–2–3 is a cycle, and 4–5 is cut off from the rest. V − 1 edges alone is not enough.

B. V − 1 edges works only together with "connected" or "no cycles". That is why you also need a DFS.

C. No vertex alone is not the same as connected: 4 and 5 cannot reach 1.

18.2 Bipartite graphs

Two sides, and edges only go across.

18.2 · Bipartite graphs

Two sides; every edge crosses

  • Two sets of vertices: \( \mathcal{A} \) and \( \mathcal{B} \).
  • \( \mathcal{A} \cup \mathcal{B} = \mathcal{V} \), \( \mathcal{A} \cap \mathcal{B} = \varnothing \).
  • Every edge joins \( \mathcal{A} \) and \( \mathcal{B} \).
  • Students–courses, users–movies.

Adapted from de la Cueva et al. (2020), Fig. 10.15.

18.3 Euler and Hamilton

Every edge once, or every vertex once.

18.3 · Euler and Hamilton

Euler: use every edge exactly once

  • Euler path: ends somewhere else. Exactly 2 odd vertices: start and end.
  • Euler circuit: back to the start. Every degree is even.

More than 2 odd vertices: impossible. Adapted from de la Cueva et al. (2020), Fig. 10.19.

18.3 · Euler and Hamilton

Hamilton: visit every vertex exactly once

  • A Hamilton cycle: visit every vertex once and come back.
  • No fast algorithm is known: it is NP-complete.

Adapted from de la Cueva et al. (2020), Fig. 10.18. Weiss (2014), § 9.7.

Checkpoint

The bowtie: two triangles 1–2–3 and 3–4–5 that share vertex 3. Which statement is true?

A. Correct. Degrees 2, 2, 4, 2, 2 are all even: Euler circuit 1 2 3 4 5 3 1. But a Hamilton cycle would pass 3 twice.

B. Backwards. Every way between {1, 2} and {4, 5} goes through 3, so a cycle through all vertices must pass 3 twice.

C. The Euler circuit repeats vertex 3. That is fine for Euler, not for Hamilton.

Self-study

isTree: count the edges, then one DFS


bool isTree(const ListGraph& g, int n, int m) {   // undirected, m edges
    if (m != n - 1) return false;          // a tree has exactly n - 1 edges
    std::vector<bool> visited(n + 1, false);
    std::vector<int> order;
    dfs(g, 1, visited, order);             // the DFS of P17
    return (int)order.size() == n;         // did DFS reach every vertex?
}

V − 1 edges + connected → no cycles. O(V + E).

Self-study

hasCycle: an edge into the call stack


enum State { NOT_DISCOVERED, ON_STACK, EXPANDED };

bool hasCycle(const ListGraph& g, int v, std::vector<State>& st) {
    st[v] = ON_STACK;                         // v is on the current path
    for (int w : g.neighbors(v)) {
        if (st[w] == ON_STACK) return true;   // edge into the stack: a cycle
        if (st[w] == NOT_DISCOVERED && hasCycle(g, w, st)) return true;
    }
    st[v] = EXPANDED;                         // finished: it leaves the stack
    return false;
}

The same three states as the animation. Weiss (2014), § 9.6.4.

Self-study

isDAG: start a DFS from every new vertex


bool isDAG(const ListGraph& g, int n) {
    std::vector<State> st(n + 1, NOT_DISCOVERED);
    for (int v = 1; v <= n; ++v)
        if (st[v] == NOT_DISCOVERED && hasCycle(g, v, st)) return false;
    return true;
}

Each vertex enters the stack once, each edge is read once: O(V + E).

Self-study

isBipartite: BFS with two sides


bool isBipartite(const ListGraph& g, int n) {     // undirected
    std::vector<int> side(n + 1, -1);      // -1: no side yet
    for (int s = 1; s <= n; ++s) {
        if (side[s] != -1) continue;       // already has a side
        side[s] = 0;
        std::queue<int> q; q.push(s);
        while (!q.empty()) {
            int v = q.front(); q.pop();
            for (int w : g.neighbors(v)) {
                if (side[w] == -1) { side[w] = 1 - side[v]; q.push(w); }
                else if (side[w] == side[v]) return false;   // same side
            }
        }
    }
    return true;
}

The outer loop covers graphs in several pieces. O(V + E).

Bipartite graphs in recommender systems

  • A PyTorch Geometric tutorial (MovieLens) has two node types: users, movies.
  • Its only edges join a user and a movie: a bipartite graph.
  • A recommender tries to guess the missing user–movie edges.
